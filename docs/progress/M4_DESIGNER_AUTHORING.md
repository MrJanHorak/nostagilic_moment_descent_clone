# M4 authoring, openings and preview checkpoint

October 18, 2026. This follows [the first designer shell](M4_DESIGNER_SHELL.md) and the owner's visual feedback about ambiguous overlaps, centered openings, preview and surface choices. [M3 remains accepted](../M3_ACCEPTANCE.md). M2 hardware performance acceptance remains open; this change makes no new performance claim.

## What changed

Overlapping room volumes now have translucent red fills, red edges and an always-visible warning above the viewport. Overlap does **not** merge rooms or create passages. Invalid drafts remain editable, but export/playtest are disabled and compiled walls are withheld. The warning explains this; the validation list still focuses affected rooms. A valid selection reports connected faces and explicitly identifies all other faces as solid.

Connections now support bounded, half-unit opening offsets in [format v3](../LEVEL_DOCUMENT_FORMAT.md). Both sides share one actual world opening, including door collision and enemy routing. Existing v1/v2 files remain supported and retain their version on import. Changes needing v3 upgrade the editing copy; undo can restore the old version.

The editor also places enemies, health/ammo pickups and relay objectives; edits spawn/exit/content room and local coordinates; controls required enemy IDs; and links/unlinks relay doors on connections. Deleting an enemy removes its objective reference. Deleting a relay removes its linked doors and required ID in the same undoable command. Spawn and the single exit are protected from deletion and can be moved. Every authored relay is required, matching the existing runtime objective contract.

## Using the new tools

1. **Inspect geometry.** Choose **Solid cutaway** in the viewport's View menu to see opaque floors/walls and surface patterns. It intentionally hides three outside faces so the interior is visible; those faces remain solid in the game. **Solid exterior** displays every wall. **X-ray edit** retains the original grid and translucent view.
2. **Move an opening.** Scroll the right panel to **Opening and door**, or choose **Edit opening** in a connection row. Set width/height, then choose Center, a corner, or a custom U/V offset. Apply the opening. The panel identifies the world axes and source face used for offsets. Both rooms must have enough frame clearance. A 6-unit opening in an 8-unit corridor leaves little offset space; use a smaller opening, or move the corridor along the shared wall plane and reapply the opening to align both ends. A 16×12 room joined to a corridor at `[4,2,-16]` can use bay offset `[4,2]` and corridor offset `[0,0]`.
3. **Set open versus gated.** A connection without a door is an **OPEN passage** with a cyan frame. Choose an existing relay under **Unlock relay**, then Apply door to make it **CLOSED until that relay**. The validator rejects self-locked or cyclic routes. Choosing Always open removes the door.
4. **Style a room or face.** Select a room, then use **Face appearance**: choose All or a local face, pick a color, choose Plain/Grid/Panels/Hazard and apply. Reset face to preset removes overrides. The same data appears in solid preview, playtest and JSON. Custom image uploads remain deferred.
5. **Place content.** Select a room and use **Add mission content** in the left panel. Enter room-local XYZ and choose an enemy, pickup or relay. Select a content row to edit its room/position in the right panel. Spawn heading uses quarter turns. Required-for-completion is editable for enemies; relays are always required. Invalid placements show the shared validator's clearance/overlap errors until corrected or undone.
6. **Preview in first person.** Choose **Playtest level**, then **Start playtest**. This runs the real game from an immutable editing snapshot. Fly, fight, activate relays, complete or restart as usual. Press Esc to release the mouse, then **Return to editor**. The editing document, camera, selection, dirty state and undo history stay intact. Reopening playtest creates a fresh runtime.

Playtest runs in a dedicated same-origin frame. Its Game instance, DOM, input handlers, audio, session and render loop belong to that frame. Return explicitly ends the session/releases pointer lock, then removes the frame. A strict source/origin message check accepts the snapshot only from its parent. No runtime transforms, health, collected IDs or objective state flow back into the editor.

## Verification and remaining work

The v3 suite crosses corner openings with real swept spheres and shot traces for all six faces at all four supported yaws, verifies visible solid/collider agreement and shifted AI waypoints, checks a shifted narrow corridor, exercises a relay door at the shifted opening, validates texture ownership/disposal, rejects invalid offsets/styles/legacy fields and verifies objective-reference cleanup and reversible migration. The original v1/v2 regressions remain intact; unsupported-version tests now reject version 4.

Browser coverage authors a corner passage and relay door, styles a room, previews solids, exports/reloads unchanged JSON, adds/deletes content, moves spawn/exit, activates a relay and completes a mission with native keyboard input. Returning preserves the document byte-for-byte and retains undo history. A second playtest/return preserves an unsaved draft. Manual screenshots cover red overlap warnings, opaque patterned cutaways and first-person surfaces.

This is another M4 checkpoint, **not full milestone acceptance**. Room deletion/duplication, autosave/recovery, and a complete human-authored three-space acceptance playthrough remain. Content placement currently uses numeric room-local properties rather than content gizmos. Connections still occupy at most one opening per face. Freeform/intersecting room unions and uploaded image textures remain outside this checkpoint. Exported JSON remains the portable backup.

Lint and strict types pass for 43 source modules. All 322 unit/runtime cases, production build and `git diff --check` pass. All 16 browser cases pass in 5.7 minutes without skips, retries or unexpected results: five editor checks plus all eleven existing game regressions. [Local browser evidence](m4-authoring-browser-check.json) records the environment and individual results. The first authoring attempt exposed a test selector mismatch on a static dropdown; using the combobox's accessible role/name fixed the test. No dependency changes or fresh audit/hardware measurements were made. The new change has not run on hosted CI. No commit, push or deployment was requested or performed.
